# PAIR KICK

**2つの駒、2本の親指。自分自身の両手で協力プレイする、2対2サッカー。**

プレイヤーは1人で2つの駒を同時に操作します。左半画面で左の駒、右半画面で右の駒。
両手が別々のことをやる、その難しさと可笑しさがゲームの中身です。

外部ライブラリ・外部アセットなし。Canvas 2D と WebAudio だけで作られています。

## 起動

ES Modules を使うため、`file://` ではなくローカルサーバーが必要です。

```sh
npm start                       # node server.js（依存ゼロ）
# → http://localhost:8080
```

`python3 -m http.server 8080` でも動きます。ビルドは不要です。

`main` への push で自動的に配信されます（ワークフローは不要。`.nojekyll` で Jekyll 処理を止めています）。

（MIMEが違うとESモジュールはブラウザに拒否されます）。

## 操作

操作はひとつ。置いた地点を支点にした相対操作（スティック）です。

- **左半分＝左の駒 / 右半分＝右の駒**（担当は入れ替わりません）
- **アクションは「離す直前に指が動いていれば」出ます**。速さは問いません。
  出ないのは、指を止めてから離したときだけです
- **向きは離す直前の移動の角度**
- 指を置くとその場にジョイスティックが出ます。指を離すとフェードアウトします
- **スティックは指に付いてきます**（ブロスタ式）。外周より外へ指を動かすと、土台がそのぶん
  指のほうへ寄ってきます。遠くまで引っ張っても土台が置き去りにならないので、
  反対へ切り返すときは外周の直径ぶん動かすだけで向きが変わり、小回りが効きます（`stick.followAt`）
- 置いた直後の指のぶれで駒が動き出さないよう、外周の8%の遊びがあります（`stick.deadZone`）。
  遊びの外は0から滑らかに速くなり、外周の85%まで倒せば最高速です（`stick.fullAt`）

| 入力 | 効果 |
|---|---|
| 自分の半画面をタッチ | その地点にフロート式ジョイスティックが出現 |
| ドラッグ | 移動（方向 × 倒し量 = 速度）。外周を越えるとスティックが指に付いてくる。**どれだけ動かしてもアクションは出ません** |
| 動かしながら離す | **踏み込み**（体当たり） |
| 止めてから離す | 何も起きない |

**払った向きは、狙いではありません。** 払う動きは「今アクションを起こす」という
合図なだけで、向きは**そのときスティックが倒れている向き**から取ります。
最後に指をどちらへ走らせたかは関係ありません。
（払い戻して中央へ帰ってきた場合だけ、直前の倒し向きを使います）

速さのしきい値はありません。実測で 49px/s のごく遅い動きでも発火します。
撃ちたくないときは `config.js` の `stick.restMs`（既定120ms）以上、
**指を止めてから離す**のが取り消し操作です。

### 設定

タイトル画面で変えられます。どれも端末に保存されます。

- **スティックの大きさ**（25%〜100%）：100% が外周の半径 60px。小さくすると、
  指を少し動かすだけで最高速になります。動かしているあいだはカードの上に実寸の見本が出ます。
  ノブは指に隠れないよう 9px より小さくはしません

横持ちではカードを横に広げて2列にし、左にこれまでの中身、右にスティックの大きさを置きます。
画面が低くてカードが収まらないときは、カードを縦にスクロールできます。

#### 廃止した設定

- **タップでタックル**（操作方法の切り替え）：廃止しました。アクションはスティックを離す操作だけです
- **タックルの向きの補正**（近くへ補正・補正する距離・補正する角度。旧 `src/aim.js`）：廃止しました。
  踏み込む向きは常にスティックの向きどおりです

### ボット戦のメニュー

ボット戦の試合中は左上に **メニュー** ボタンが出ます。押すと試合が一時停止し、

- **試合に戻る**：続きから再開（カードの外を押しても戻ります）
- **ホームへ**：試合をやめてタイトルへ戻ります

アプリを離れた（別のアプリに切り替えた）ときも、自動で一時停止してメニューを開きます。

### アクションはひとつしかない

「蹴る」という専用の動作はありません。**ボールを持っていようがいまいが、
やることは同じ踏み込み（体当たり）ひとつ**です。
違うのは踏み込んだ先に何があるかだけ。

| 踏み込んだ先 | 起きること |
|---|---|
| ボール | 体が当たって飛ぶ（＝これがキック） |
| 相手 | 相手が**1秒動けなくなる**（表面に ✕ が出る） |
| 何もない | ただの加速。コースを切る・追いつく |

ボールが飛ぶ向きは**駒の中心 → ボール**。入力の角度では決められません。
入力を −90°/0°/90°/180° と振っても、ボールが駒の真右にある限り
飛ぶ向きは 0° のままです（実測済み）。狙うには**体を置き直す**しかありません。

踏み込みで叩いたボールは 572〜750 まで出ます（駒の足の速さは 260）。
運ぶより蹴るほうが速いのは変わりません。

### 体当たり

踏み込んで相手にぶつかると、**ぶつけられた側が1秒動けなくなります**。
そのあいだ駒の表面に ✕ が重なり、消える直前だけ薄くなります。
自分の2駒どうしでは起きません（押し合いはします）。
潰されている間は踏み込めず、クールダウンも消費しません。
既に潰れている相手を上塗りして時間を伸ばすこともできません。

### 進行方向の矢印

動かしているあいだ、駒の前に**短く太い半透明の矢印**が出ます。
示すのは進行方向で、そのまま離したときにダッシュする向きでもあります。
ボールの行き先の予告ではありません（それは体の置き方で決まります）。

駒の担当は固定です。左の駒が右サイドまで走っても、左半画面は左の駒のまま。
クールダウンは駒ごとに0.8秒（外周アークで表示）。アクションは1種類しかないので、
これがそのまま「次にぶつかりに行けるまで」の間隔になります。

デスクトップ検証用：マウスドラッグ＝タッチ1本、`WASD`＝左駒 / `矢印`＝右駒、`E`＝左踏み込み / `右Shift`＝右踏み込み。

## 対人戦

タイトル画面で「対人戦」を選ぶと、同じサーバーに繋いだ相手と2人でマッチングします。
2人そろうと自動で始まり、片方が抜けると相手に伝わります。

試合を進めるのは**サーバー**です。クライアントが送るのは「意図」だけで、位置は
サーバーが計算して60Hzで配ります。`src/game.js` がブラウザAPIに触れない純粋な
モジュールなので、同じものを Node でそのまま動かしています。

- サーバーの返事を待ってから動かすと、往復の通信時間ぶん操作が遅れます。そこで
  クライアントも同じ `step()` で**自分の入力を先に反映**します（予測）。
  入力には通し番号を付け、サーバーは「どこまで使ったか」を状態と一緒に返します。
  クライアントは届いた状態を正解として置き直し、まだ使われていない自分の入力を
  再生して「今」に戻します。ずれた分は瞬間移動させず、数フレームかけて寄せます
- 相手の入力は届かないので、直前の移動入力を続けているものとして予測します
- 入力はサーバー側で1ステップに1つずつ順に使います。溜まりすぎたら古いものを
  捨てて追いつきますが、踏み込みだけは捨てずに次へ引き継ぎます。通信の揺らぎで
  一度溜まった入力は自然には減らないので、余分に溜まったままなら少しずつ捨てて縮めます
- 入力が次のステップに間に合わなかったときは、直前の移動で進めたうえで
  「その番号の入力は使った」ことにします（先借り。最大4ステップ）。遅れて届いた入力は
  二重に使わず、踏み込みだけ次のステップへ回します。こうしないと駒が1ステップ余計に進み、
  あとで捨てて戻すことになって、本人の画面で駒がワープします。120Hzの画面の端末は
  ステップを進めるフレームが偶数・奇数で入れ替わり、入力の届く間隔が揺れやすいので、
  120Hzの人だけがラグく感じる原因になっていました
- 回線が詰まっている相手には状態を送らずに飛ばします（毎回丸ごと送っているので、
  次ので追いつけます）。古い状態が列をなして遅れが積み上がるのを防ぐためです。
  送信待ちが約12個ぶん（4KB・0.2秒）を超えたら飛ばします。以前は32KB（約1.6秒ぶん）まで
  溜めていたため、回線が一瞬止まると、復帰後も古い状態を順に受け取り終えるまで新しい状態が
  届かず、ラグが尾を引いていました。入力とイベントつきの状態は落とせないので大きめの上限です
- 対人戦中は右上に通信の往復時間を出します。ここが大きい（目安 150ms 以上）と、
  自分の駒は即座に動いても、相手やボールとの競り合いでずれが見えやすくなります。
  これは距離で決まるので、サーバーを遊ぶ人の近くに置くのがいちばん効きます
  （日本から遊ぶなら Render の Singapore リージョンなど）
- 音や演出は、自分の操作と物理の反応は手元の予測から即座に、相手の踏み込み・
  キック・体当たりとゴール・キックオフ・決着はサーバーから出します（二重に鳴らさない）
- 後から入った側（team 1）は**盤面を180度回して**表示します。回さないと
  「自分の駒が手前・攻める方向が奥」が崩れ、左右の担当も意味を失います。
  送る意図の向きと2駒の割り当ても、それに合わせて入れ替えています
- 色は**見る側から見た相対**です。どちらのプレイヤーからも自分がコーラル、
  相手がシアンに見えます。スコアも自分が左

### なめらかに描く

物理は 1/60 秒刻みで進みますが、画面は 120Hz など別の間隔で描かれます。そのまま描くと
駒が「進む・止まる」を交互に繰り返してカクつくので、直近2ステップの位置を覚えておき、
描くときはそのあいだを経過時間で補っています（`src/main.js` の `updateView`）。
120Hz を真似た計測で、動かしている駒が止まって見えるフレームが 87 中 45 → 0 になりました。

駒とボールの影は、毎フレーム `shadowBlur` で描くと重い（特に iOS Safari）ため、
一度だけぼかした画像を作って貼っています。画面の細かさは最大2倍で描きます
（3倍の画面でも見た目はほぼ同じで、塗る画素が半分以下になります）。

試合中も出ているスコアとバナーには、すりガラス（`backdrop-filter`）を使っていません。
背後のキャンバスが毎フレーム描き変わるため、ぼかしも毎フレーム計算し直しになるからです。
タイトルなどの画面は、消えたら `visibility: hidden` で描画から外します
（透明にするだけだと、画面全体を覆うぼかしが試合中も残ります）。

### 名前・成績・レート

対人戦を選ぶと、タイトルに**名前**の欄と成績（レート・勝ち・負け）が出ます。
名前（12文字まで）は相手と観戦者に見え、試合中は右上に「vs 相手の名前（レート）」と出ます。

- レートはイロレーティング（初期 1500、K=32）。同じレートどうしなら勝ちで +16、負けで −16。
  格上に勝つほど大きく上がります。結果画面に増減が出ます
- 数えるのは対人戦だけ。決着した試合のほか、相手が途中で抜けたら**勝ち**、自分が途中で
  やめたら**負け**です。試合中にアプリを閉じた場合は、次に開いたときに負けとして数えます
  （始まった時点で「途中の試合」を記録しておき、決着したら消すため）
- 名前と成績は**端末に保存**します（`src/profile.js`）。サーバーは保存しません
  （無料のホスティングは再起動で消えるため）。そのため端末を替えると引き継がれず、
  相手のレートは相手が名乗った値を使います。気軽に遊ぶための目安です

### 観戦

タイトルで「観戦」を選ぶと、いま進んでいる対人戦の一覧（名前・得点・観戦人数）が出ます。
選ぶとその試合を見られます。左上の「観戦をやめる」で一覧へ戻ります。

- 一覧は `/rooms`（HTTP）、観戦は `/ws` に `{ t: 'watch', id }` を送って状態を受け取ります
- 観戦者へは状態を間引いて（約30Hz）送り、観戦側は 110ms 遅らせて前後の状態のあいだを
  補って描きます（`src/spectate.js`）。音や演出も、その状態を描くときに出します
- サーバーで進めている試合はサーバーが配ります。**Wi-Fi直結の試合**はサーバーが状態を
  持っていないので、観戦者がいるあいだだけホストが状態をサーバーへ送り、サーバーがそのまま
  中継します（観戦者がいなければ送りません）。得点だけは一覧のためにいつも知らせます
- 観戦者は操作できません。1試合あたり20人まで。プレイヤーには右上に観戦人数が出ます

### 同じWi-Fiなら直結

2人が同じWi-Fiにつないでいると、**サーバーを経由せず端末どうしで直接つなぎます**
（WebRTC のデータチャネル）。サーバーまでの往復がなくなるので、通信の往復時間は
数ms程度まで縮みます。右上の表示が「対人戦 · Wi-Fi直結」になっていれば直結です。

- マッチングのあと、試合を始める前に直結を試します。接続情報のやりとりだけは
  サーバーが中継します（`'pair'` → `'rtc'` の中継 → ホストが `'mode'` で結果を知らせる）
- 直結できたら、先に入った側（team 0、ホスト）の端末が `src/match.js` で試合を進め、
  相手へ配ります。試合はタイマーではなくホスト自身のステップに合わせて1つずつ進めるので、
  ホストの入力は必ず間に合います。サーバーで動いているのと同じコードで、やりとりの中身も同じなので、
  予測・答え合わせはそのまま働きます。ホスト自身の入力は通信なしでその場で渡します
- STUN/TURN サーバーは使いません。端末自身のアドレスどうしでしかつながらないので、
  実質「同じネットワークにいるときだけ」直結になります。別々の回線にいる相手とは
  3.5秒ほど試したあと、これまでどおりサーバー経由で始まります
- ゲストWi-Fiや一部のルーターは端末どうしの通信を止めている（APアイソレーション）ため、
  同じWi-Fiでも直結できないことがあります。その場合もサーバー経由で遊べます
- 状態は「届かなくても再送しない」経路で送ります。毎回丸ごと送っているので、
  1つ落ちても次ので追いつけます。確実に届く経路だと、Wi-Fiで1つ落ちただけで
  後ろの状態がすべて再送待ちになります。入力と、イベント（ゴール・決着など）が
  載った状態だけは確実に届く経路で送ります
- **直結の試合でも、入力と状態は直結とサーバー経由の両方で送ります。** 受け取る側は
  通し番号で先に届いたほうだけを使う（遅いほうは捨てる。イベントも二重に鳴らさない）ので、
  その時々で速いほうの経路が自動で使われます。Wi-Fiが一瞬詰まってもサーバー経由が埋め、
  詰まりが解ければ直結に戻ります。右上には、いま主に使っている経路（「Wi-Fi直結」か
  「通信経由」）が出ます。計測（直結を1.5秒止める）：これまではゲストの画面が最大94ステップ
  （約1.5秒）遅れたのが、0〜1ステップのまま続くようになりました
- 直結が切れても、サーバー経由で試合を続けます（これまでは試合が終わっていました）。
  逆にサーバーとの接続が切れても直結で続きます。両方が切れたら「相手が切断しました」です。
  サーバーが「相手が抜けた」と知らせてきたときは、直結からも1秒何も届かなければ終えます
- 直結中にサーバーとの接続が切れても試合は続きます。相手が抜けた・Wi-Fiから外れた
  （5秒何も届かない）ときは「相手が切断しました」になります
- マッチングにはサーバーが要るので、直結でも `server.js` は動かしておく必要があります

**GitHub Pages では対人戦は動きません**（静的配信のみで WebSocket サーバーを
置けないため）。対人戦を使うには `server.js` を動かしてください。Render の
Blueprint は Web Service になっているので、そのままデプロイすれば動きます。

## ホーム画面に追加

`manifest.webmanifest` と `sw.js` を置いてあるので、ホーム画面に追加すると
アドレスバーなしの全画面で起動し、オフラインでも遊べます（ボット戦のみ。
対人戦は当然ながら通信が要ります）。

iOS は Safari の共有メニューから「ホーム画面に追加」、Android は Chrome の
メニューから「アプリをインストール」です。

## ルール

3点先取。オウンゴールは有効。

**キックオフ** — ボールは必ずセンターに置かれ、**失点した側がボールに触れた瞬間**に
試合が始まります。カウントダウンはありません。触れるまでは相手は自陣で静止したまま
待つので、息を整えてから再開できます。触れ方は自由で、歩いて当てても、寄って蹴っても
かまいません（蹴ればそのまま最初のパスになります）。
ラリーが続くとボールが加速し、白 → 黄 → 橙へ発光していきます（得点でリセット）。
自駒間でパスが繋がると光の糸が閃き、繋ぐほど音が1音ずつ上がっていきます（8段でトップ）。

### ボールの当たり方

駒とボールの反発は、**ぶつかる速さで変わります**。

| ぶつかる速さ | 反発 | 実測（跳ね返る速さ） |
|---|---|---|
| 260（駒の足の速さ＝普通に触れた） | 0.08 | 21（0.08倍） |
| 520（踏み込みで叩いた） | 0.48 | 252 |
| 640（飛んできた球が体に当たった） | 0.69 | 442 |

普通に触れただけならボールは跳ね返らず、**駒の 1.08 倍の速さで前へ押されます**。
押し続けているあいだは足元に残るので運べますが、これは吸着ではありません。
直角に曲がれば 0.5 秒で接触距離の 4 倍（140）まで置き去りになります。
運ぶ速さ（260）に対し、踏み込みで叩けば 572〜750 出るので、
**蹴るほうが速いことは変わりません**。

一律で反発を寝かせるとシュートが守備の体で死んでこぼれ球が出ず、
ボット同士の試合が守り合いのまま終わらなくなりました（120試合で決着なしが 0 → 3 件、
無得点が420秒続いた試合まで発生）。速さで切り分けることでこれを戻しています
（同条件で決着なし 0 件、得点間隔の99%点は 236秒 → 124秒）。

膠着の検出も速さではなく**移動量**で見ています。小突かれ続けているボールは
毎フレーム動いているので、速さで見ると素通りしてしまうためです
（`match.stuckRadius` の円から `stuckSeconds` 出られなければ中央へ押し出す）。

## 画面の向き

縦持ち・横持ちのどちらでも遊べます。

コートが横に広い（1350×1600）ので、どの向きでも全体は画面に収まりません。
追従カメラが動きます。注視点は「ボールと自分の2駒」で、その広がりに応じて
ズームが変わります。相手の駒は注視点に入れていません（カメラを予測可能に保つため）。

どちらの操作でも、視点は少しコート外まで出られます。駒がタッチラインに
寄ったときに画面の端へ貼り付いて、その先が読めなくなるのを避けるためです。

スティック操作では、寄れる上限を「コート縦の40%・横の55%を必ず残す」線で
止めてあります。これ以上寄るとパスの受け手が画面外に出てしまい、
「パスは武器」という柱が成立しなくなるためです。引きの下限はコート全体です。


ジョイスティックと左右の担当分けは**画面座標**で処理しています。カメラが動いても
スティックが流れないこと、「画面の左半分＝左の駒」がコート上の左右と無関係に
成り立つことは、この分離があってこそです。HUD もカメラ倍率とは切り離してあるので、
向きを変えても文字の大きさは変わりません。

## コート・駒の大きさ・速さ

`config.js` の先頭にある3つの数字だけで決まります。

```js
const WORLD = 2;    // コートの拡大率（各辺）。面積は WORLD² 倍
const PIECE = 0.5;  // 駒とボールの大きさ。現行の見た目を 1 とした比率
const PACE  = 0.5;  // 全体の速さ。0.5 = すべて半分の速さ
const WIDE  = 1.5;  // コートの横だけを伸ばす比率。縦は変えない
```

`PACE` は「シミュレーションの時間を引き伸ばす」つまみです。速度に `PACE` を掛け、
時定数を `PACE` で割ります（摩擦だけは指数減衰なので `f^PACE`）。
これで `x'(t) = x(PACE·t)` が成り立ち、**軌道の形と届く距離は変わらず、
同じ試合をそのまま半分の速さで見ている状態**になります。

速度を半分にするだけでは駄目で、摩擦がそのままだとボールの到達距離も半分に
なります。キック1発がコート長辺の23%しか進まなくなり、パスが武器でなくなります。
だから摩擦とダッシュ時間を合わせて動かしています。

`goalPause`（得点後の停止）は演出の間合いなので `PACE` に追従しません。

距離と速度は `WORLD` に追従させてあるため、コートを広げても
「キック1発がコートの何割を進むか」は変わりません。

現行値（コート 1350×1600 / 駒は従来の半分の見た目 / 速さ半分）での実測：
踏み込みの移動距離が **156px**、コート縦断が **6.15秒**。
`PACE` を変えても、この2つは変わりません。

駒をもっと小さくしたければ `PIECE` を 0.25 に、元に戻したければ 1 にしてください。

`game.js` はブラウザAPIに一切触れません。`step(state, intents, dt)` が意図を受け取り、
状態を進め、発生したイベントの配列を返すだけです。対人戦のサーバーは、この同じ
モジュールを Node でそのまま動かしています（`net/rooms.js`）。

ボットも例外なく `intents` 経由で動きます。内部でボールに直接速度を代入するズルはしていません。

キックの向きが体の置き方でしか決まらないので、ボットの思考も2段になっています。

1. どこへ蹴りたいかの候補を優先順に出す（シュート / パス / クリア）
2. その「裏」へ回り込み、飛ぶ向きが候補に乗ったら踏み込む

回り込みは、ボールに触れない半径で円周上を回ります。まっすぐ裏へ向かうと
ボールを突っ切って押してしまい、狙いが崩れるためです。
候補を1つに絞らないのは、一番いい狙いに揃うのを待つより、既に体が向いている先で
使えるものを取るほうが速いから。許せる角度のずれは的ごとに違います
（ゴール口は広い、相方は点）。後ろ向きの候補は入れていないので、
妥協して蹴っても自陣へは飛びません。

**体当たりは支援側の役割**にしてあります。ボールを追う側にもやらせると、
両チームの追う側どうしが至近で潰し合い、ボールが誰の物にもならないまま
試合が進まなくなりました（実測で1点あたり59秒）。
狙うのは**ボールではなく、ボールを持っている相手そのもの**です。
ボールへ突っ込むと飛ぶ向きが位置関係で決まってしまい、自陣へ叩き返すほうが
多くなります（実測でオウンゴールが得点の18%に達しました）。

ボット同士の試合は 137秒 → 約186秒、パス本数は 12.4 → 約9.3 になりました。
**指で向きを決められないぶん、蹴る前に体を作る時間が要る**という設計そのものの
帰結です（人間側も同じ制約を受けます）。


## CPUレベル（1〜100）

「ボット」を選んだタイトル画面・再戦画面でCPUレベルを指定できます。初期値は **Lv.3**。従来の反応間隔、狙いのぶれ、キック判断をLv.3の基準にしています。移動性能統一のため、従来CPUだけにあった0.9倍の速度補正は撤廃しました。そのためLv.3は従来の強さの目安です。

- Lv.1〜2: 判断が遅く、狙いや先読みが不正確な入門向け。
- Lv.4〜39: 反応と精度を徐々に高め、相手の位置を見たシュートコース選択や、相手の移動を予測したパスコース判断を強化します。
- Lv.40〜79: 強化AIを使用。ボールの摩擦・壁反射を予測し、到達時間で追う担当を決めます。シュート・パスの候補と、同じ物理処理で踏み込んだ結果を比較します。
- **Lv.80〜100: 自分2人対CPU3人**。ボール担当・サポート・最後尾のカバーを分担します。レベルを下げた再戦や対人戦では2対2に戻ります。
- **Lv.100「神級」**: 毎フレーム判断を更新し、狙いのランダム誤差はゼロ。11通りのゴールコースを調べ、最大4通りの踏み込み候補を20ステップ先まで実際の物理で比較します。ボールの軌道は最大2秒先まで予測します。
- 速度・加速度・駒の大きさ・踏み込み性能・キック威力・クールダウンは全レベル・人間で共通です。同じ入力は同じ物理処理を通ります。
- 2〜3体のCPUは同じレベル設定を使います。選択画面に人数を、試合中の右上に実際のCPUレベルと人数を表示します。
- 選択したレベルを端末に保存し、再戦開始時に新しい設定を適用します。対人戦ではCPU設定を隠します。
- 未指定や不正値はLv.3、小数は四捨五入、範囲外は1〜100へ補正します。

難易度は判断パラメータの段階であり、隣接レベル間で必ず勝率が上がることを保証するものではありません。
「神級」は最高難度の名称です。相手の未来の入力を読むことや、得点・速度を直接書き換える処理はなく、無敗の保証ではありません。予測用の試合はコピー上で進め、本物の試合へは通常の移動と踏み込み入力だけを返します。

### CPUの検証

npm test で、全100レベルの判断・入力・座標の健全性、Lv.3の基準値、両駒の移動入力、同じ入力での物理結果、コース選択、再戦用CPUの初期化を確認できます。外部テスト依存はありません。
3人編成の境界、3人目による得点、人数切替時の状態リセット、予測中に試合を改変しないことも検証します。

`npm run benchmark:cpu` は、前回のLv.100（コミット `58144f1`）と固定乱数・各12試合・180秒上限で比較します。2対2はチームを交替し、2対3は実ゲームと同じ配置です。実行にはGitとそのコミットを含む履歴が必要です。
