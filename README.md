# PAIR KICK

**2つの駒、2本の親指。自分自身の両手で協力プレイする、2対2サッカー。**

プレイヤーは1人で2つの駒を同時に操作します。左半画面で左の駒、右半画面で右の駒。
両手が別々のことをやる、その難しさと可笑しさがゲームの中身です。

外部ライブラリ・外部アセットなし。Canvas 2D と WebAudio だけで作られています。

## 起動

ES Modules を使うため、`file://` ではなくローカルサーバーが必要です。

```sh
npm start                       # node server.js（依存ゼロ）
# → http://localhost:8080
```

`python3 -m http.server 8080` でも動きます。ビルドは不要です。

## 公開

ビルド成果物がないので、リポジトリの中身をそのまま配信すれば動きます。

**GitHub Pages** — このリポジトリは Pages のソースが `main` ブランチのルートに設定済みで、
`main` への push で自動的に配信されます（ワークフローは不要。`.nojekyll` で Jekyll 処理を止めています）。
公開URLは <https://hsgwyuki0429-design.github.io/W-soccer/> です。
サブパス配信になるため、アセット参照はすべて相対パスにしてあります。

**Render** — リポジトリを指定すれば `render.yaml` を読んで静的サイトとして配信します。
Web Service として動かしたい場合は `render.yaml` 末尾のコメントの設定に差し替えてください。
`server.js` が `PORT` を読み、`.js` に `text/javascript` を付けて配信します
（MIMEが違うとESモジュールはブラウザに拒否されます）。

## 操作

| 入力 | 効果 |
|---|---|
| 自分の半画面をタッチ | その地点にフロート式ジョイスティックが出現。左半分＝左の駒、右半分＝右の駒 |
| ドラッグ | 移動（方向 × 倒し量 = 速度）。**どれだけ速く動かしてもアクションは出ません** |
| スワイプしながら離す（ボール至近） | **キック** |
| スワイプしながら離す（ボールなし） | **ダッシュ**（0.15秒の瞬間加速。体当たり・タックル・コース切り） |
| 止めてから離す | 何も起きない。指を離すだけ |

アクションが出るのは指を離す瞬間だけです。直前 110ms の移動量がしきい値を超えていれば、
その方向へキック / ダッシュ。止まった状態で離せば何も起きないので、
「動かす」と「撃つ」を指1本の中で撃ち分けられます。

駒の担当は固定です。左の駒が右サイドまで走っても、左半画面は左の駒のまま。
クールダウンは駒ごとに0.4秒、キックとダッシュで共有（外周アークで表示）。

デスクトップ検証用：マウスドラッグ＝タッチ1本、`WASD`＝左駒 / `矢印`＝右駒、`E`＝左ダッシュ / `右Shift`＝右ダッシュ。

## ルール

3点先取。失点した側のボールで再開。オウンゴールは有効。
ラリーが続くとボールが加速し、白 → 黄 → 橙へ発光していきます（得点でリセット）。
自駒間でパスが繋がると光の糸が閃き、繋ぐほど音が1音ずつ上がっていきます（8段でトップ）。

## 画面の向き

縦持ち・横持ちのどちらでも遊べます。

**縦持ち**はコート全体が画面に収まります（従来どおり。倍率も配置も変わりません）。

**横持ち**はコートが収まらないので、追従カメラが動きます。注視点は
「ボールと自分の2駒」で、その広がりに応じてズームが変わります。相手の駒は
注視点に入れていません（カメラを予測可能に保つため）。

寄れる上限は「コート縦の46%が見える」ところで止めてあります。これ以上寄ると
パスの受け手が画面外に出てしまい、「パスは武器」という柱が成立しなくなるためです。
引きの下限はコート全体です。

ジョイスティックと左右の担当分けは**画面座標**で処理しています。カメラが動いても
スティックが流れないこと、「画面の左半分＝左の駒」がコート上の左右と無関係に
成り立つことは、この分離があってこそです。HUD もカメラ倍率とは切り離してあるので、
向きを変えても文字の大きさは変わりません。

## コート・駒の大きさ・速さ

`config.js` の先頭にある3つの数字だけで決まります。

```js
const WORLD = 2;    // コートの拡大率（各辺）。面積は WORLD² 倍
const PIECE = 0.5;  // 駒とボールの大きさ。現行の見た目を 1 とした比率
const PACE  = 0.5;  // 全体の速さ。0.5 = すべて半分の速さ
```

`PACE` は「シミュレーションの時間を引き伸ばす」つまみです。速度に `PACE` を掛け、
時定数を `PACE` で割ります（摩擦だけは指数減衰なので `f^PACE`）。
これで `x'(t) = x(PACE·t)` が成り立ち、**軌道の形と届く距離は変わらず、
同じ試合をそのまま半分の速さで見ている状態**になります。

速度を半分にするだけでは駄目で、摩擦がそのままだとボールの到達距離も半分に
なります。キック1発がコート長辺の23%しか進まなくなり、パスが武器でなくなります。
だから摩擦とダッシュ時間を合わせて動かしています。

`readySeconds` と `goalPause` は演出の間合いなので `PACE` に追従しません。

距離と速度は `WORLD` に追従させてあるため、コートを広げても
「キック1発がコートの何割を進むか」は変わりません。

現行値（900×1600 / 駒は縦持ちで従来の半分の見た目 / 速さ半分）での実測：
キック1発の到達距離がコート長辺の **46.7%**、ダッシュの踏み込みが **156px**、
コート縦断が **6.15秒**。到達距離とダッシュ距離は `PACE` を変えても不変です。

駒をもっと小さくしたければ `PIECE` を 0.25 に、元に戻したければ 1 にしてください。

`game.js` はブラウザAPIに一切触れません。`step(state, intents, dt)` が意図を受け取り、
状態を進め、発生したイベントの配列を返すだけです。将来 socket.io で対人戦に移行するときは、
このモジュールをそのままサーバーへ持っていけます。

ボットも例外なく `intents` 経由で動きます。内部でボールに直接速度を代入するズルはしていません。
